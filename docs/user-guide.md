# IR 工作台使用指南（Analysis Plan Studio）

> 心法一句话：**先和工具约定好这次分析怎么做，确认后它受控执行，再按约定验收结果**。
> 你只需要做四个动作：填约定（①②）→ 按确认（③）→ 做验收（④）→ 审变更（⑤）；其余检查机器自动把关，你不出手流程就停住，绝不静默放行。

## 1. 启动与退出

- 双击仓库根目录 `启动分析计划工作台.command` → 自动装依赖(首次)、构建界面(首次)、起本机服务并打开浏览器
- 端口：优先 8765，被其他进程占用时自动顺延 8766-8768（页面地址以弹出的浏览器为准）
- 退出：焦点切到对应 Terminal 窗口按 `Ctrl+C`（或直接关窗口）
- 数据位置：`projects/default/`（本机独有，不随 git 同步；换机拷这个目录即可迁移）
- 再双击一次 = 复用已运行的服务，直接开界面

## 2. 五个页面怎么用

| 页面 | 你做什么 | 什么时候算完成 |
|---|---|---|
| ① 项目与模板 | 新任务入口在②；历史任务点「打开」恢复 | 看到计划列表与状态 |
| ② 分析计划 | 填业务问题、决策用途、基期/报告期两段日期 → 「从模板创建草稿」 | 生成计划，跳转数据页 |
| ③ 数据与口径 | 填 CSV 路径；三个口径选实值（税/优惠/退款归属）；覆盖清单日期（逗号分隔）；可选门店资格清单 → 「校验并绑定」 | 无警告直接过；有警告点「已知悉，继续」 |
| ④ 检查与确认 | 「执行检查」看 G0 结果 → 「编译执行清单并确认计划」 | 显示确认记录（六类摘要）；跳转运行页 |
| ⑤ 运行与验收 | 「启动运行」→「回收证据并验证」→「接受/带限制/退回」→「生成自动发现」；可选：录待验证、比版本、提变更 | 验证 PASSED 且已接受 |

## 3. 数据文件要求（CSV）

| 列名 | 含义 | 问题会怎样 |
|---|---|---|
| `row_id` | 唯一行标识 | 缺失/重复 → 质量检查 FAIL，运行失败（不会静默去重） |
| `business_date` | 业务日期 `YYYY-MM-DD` | 解析失败 → 绑定即阻断 |
| `store_id` / `category_id` | 门店/品类 | 缺列 → 绑定时定位到字段报错 |
| `net_sales_amount` | 净销售额（数值） | — |
| `currency` | 币种列 | 混合币种 → 阻断 |

**覆盖清单**：把"哪些日期有数据"如实列出（如 `2026-07-05,2026-07-15,...`）；留空 = 声明无覆盖证明 → 走警告路径（确认时需知悉，验证会记 UNKNOWN 并阻断接受）。**不要为了过检查编日期**——检查是按数据实核的。

**门店资格清单**：想看"同店口径"才提供（store_id 一列的 CSV + 规则说明）；不提供就是"全量观察范围"，工具不会把门店交集包装成同店。

## 4. 三个状态分开看（重要）

结果页三个状态**永远分开显示**，不要只看绿色：
- **运行 COMPLETED** = 约定的计算跑完了（不代表对）
- **验证 PASSED** = 对账/覆盖/证据机器检查过了
- **已接受** = 你的人工判断（FAIL/UNKNOWN 时只能"退回"）

## 5. 常见场景

- **改了口径/期间** → ④页「变更请求」：填原因+新值 → 先生成 CR 审阅（旧值→新值）→「确认合入」产生新版本（旧确认自动失效，需重新确认）或「撤回」
- **比两个版本差在哪** → ④页「版本差异」填版本号 A/B
- **有因果猜想**（如"断货导致下降"）→ ⑤页待验证区录入；它永远不进结论区
- **导出** → ⑤页「导出计划交接包」默认不含原始数据；含数据/结果的包需显式勾选
- **下一周期** → 让工具把已验收计划存成模板，再实例化：自动清除旧批准/旧数据/旧结论，重新绑定即可（记住：复用的是方法，不是结论）

## 6. 双机使用

本机 / MacBook 各自 `git` 同步代码、各自双击启动；`projects/default` 数据不随 git 走，两边独立。跨机迁移 = 拷贝 `projects/default` 目录。
